# Long-Form Patterns

## Pattern 1: Hook to Proof to Build

Use when the final artifact is visually impressive.

- 0-15s: show the final result and state the viewer outcome.
- 15-45s: explain the problem with the old workflow.
- 45-120s: show the proof and the core mechanism.
- Middle: demonstrate the build in logical sections.
- Final: recap the repeatable workflow and CTA.

Caption approach:

- Burn in the hook, the mechanism, section names, and CTA.
- Avoid full subtitles during dense UI walkthroughs unless requested.

## Pattern 2: Mistake to Better Workflow

Use when the video teaches a production rule.

- Open with the mistake.
- Show why it breaks the result.
- Demonstrate the improved workflow.
- Show the final artifact as proof.
- End with a repeatable rule and CTA.

Caption approach:

- Caption the mistake and the rule.
- Use labels for before/after proof, not long explanatory overlays.

## Pattern 3: Stack Walkthrough

Use when the value is the combination of tools.

- Open with the final output.
- Reveal the stack and what each tool contributes.
- Show the handoff between tools.
- Use real B-roll for proof.
- End with the exact next action.

Caption approach:

- Caption tool names and handoffs.
- Keep captions separate from UI callouts so the screen remains readable.

## Minimum Acceptance Checklist

- Hook states the viewer outcome.
- B-roll matches the narration topic.
- Captions are generated from final audio.
- Key sections have readable captions or labels.
- No persistent overlay blocks the demo.
- Zooms preserve important UI.
- CTA is spoken or clearly on screen.
